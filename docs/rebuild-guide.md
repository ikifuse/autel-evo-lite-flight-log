## 2. ゼロからの再構築手順

本システムを新しいGoogleアカウントや新規環境へゼロから再構築する場合、以下の10ステップを厳格な順序で実施する。

### Step 1: スプレッドシートの新規作成と必須シートの準備
新規スプレッドシートを作成し、以下のシートを揃える。
- `日常点検`（日付シート複製用テンプレート）
- `BAT_1` ～ `BAT_7`（計7枚）
- `点検整備記録_EVO Lite_原本`
- `点検整備記録_EVO Lite+_原本`

### Step 2: 日常点検原本シートのレイアウト作成
- No.1ブロック（C:O列）およびNo.2ブロック（R:AD列）を配置する。
- 飛行前点検11項目、飛行後点検4項目のチェック欄を用意する。
- 飛行記録行の開始位置を示す見出しテキスト「`使用バッテリー`」を配置し、最大7行の飛行記録領域を確保する。
- 帳票の罫線、フォント、背景色、セル結合はテンプレート側を正本として設定する。

### Step 3: バッテリー履歴シート（BAT_1 ～ BAT_7）の準備
- 各BATシートの13行目〜212行目を履歴データ領域（A〜H列）として用意する。
- A列（日付）〜G列（飛行経路・場所）の見出しを正しく配置する。

### Step 4: 機体原本シートの累計時間ラベル配置
- 2枚の機体原本シートに、一意の検索ラベル文字列「`点検時の総飛行時間`」を配置する。
- そのラベルに隣接するセル（累計セル）に初期値 `00:00` を入力しておく。

### Step 5: システム設定ファイル（src/00_config.gs）の調整
- 作成したスプレッドシートのIDを `src/00_config.gs` の `SPREADSHEET_ID` に設定する。
- 機体モデル名（`EVO Lite`, `EVO Lite+`）、登録記号、BATリスト、ブロック定義が環境と一致していることを確認する。

### Step 6: ソースコードの構成確認
- すべての機能実装が `src/` 配下の各ファイルに正本として存在することを確認する。
- UIのCSS・HTMLシェルと `scripts/web-source-order.json` 順のJavaScriptを `APP_HTML` へ組み立てることを確認する。責務と依存方向は [architecture.md](architecture.md) を参照する。

### Step 7: ローカルビルドの実行
- `scripts/source-order.json` の結合順に従い、ビルドスクリプトを実行して `dist/Code.gs` を生成する。
  ```bash
  node scripts/build.mjs
  node scripts/build.mjs --check
  ```

### Step 8: テストスイートの全件実行
- 回帰テストおよび障害注入テストを実行し、すべてのテストがパスすることを確認する。
  ```bash
  node tests/regression.test.js
  node tests/refactor-compat.test.js
  node tests/web-compat.test.js
  node scripts/check-boundaries.mjs --self-test
  node scripts/check-boundaries.mjs
  ```
- B案互換試験には基準commitを含むGit履歴が必要。ローカル検証の範囲と実GAS・実機での確認事項は [test-spec.md](test-spec.md) を参照する。

### Step 9: GASプロジェクトへの反映とデプロイ
- 後述の「第3章 GASへのデプロイ手順」に従い、GASエディタへ `dist/Code.gs` の全文を貼り付け、Webアプリとしてデプロイする。

### Step 10: 実機（Pixel 6a等）での動作検証
- デプロイされたWebアプリURLを実機ブラウザで開き、初期表示、運航開始、点検、飛行、着陸、一括保存、再読込、および「アプリテスト」モードによる保存結果を実機上で確認する。

## 3. GASへのデプロイ手順

本番運用中のGASプロジェクトへ最新コードを反映する場合の手順。

1. **GitHub Actionsの完了確認**:
   - リモートリポジトリのCI（GitHub Actions）が成功し、`dist/Code.gs` が最新コミットと完全に整合していることを確認する。
2. **生成コードのコピー**:
   - リポジトリ内の `dist/Code.gs`（自動生成ファイル）の全文をクリップボードにコピーする。
3. **GASエディタへの貼り付け**:
   - 対象のGoogle Apps Scriptプロジェクトを開く。
   - 単一の `Code.gs` を開き、既存コードを全選択して最新コードで全文貼り替える。
   - **注意**: GAS側に `src/` のような分割ファイルを作成したり、手動でコードを部分編集したりしないこと。
4. **プロジェクトの保存**:
   - エディタの「保存」アイコンを押下する。
5. **Webアプリのデプロイ更新**:
   - 右上の「デプロイ」>「デプロイを管理」を開く。
   - 既存のアクティブなWebアプリデプロイを選択し、鉛筆アイコン（編集）を押下する。
   - バージョンを「**新バージョン**」に指定し、必要に応じて説明（例: `v1.0.1 UI修正`）を入力して「デプロイ」を押下する。
6. **アクセス権限・実行ユーザーの確認**:
   - 「次のユーザーとして実行」: **自分（所有者）**
   - 「アクセスできるユーザー」: **自分のみ**（または運用方針に応じた設定）になっていることを目視確認する。
7. **実機でのリロードとバージョン確認**:
   - Pixel 6a実機のブラウザでWebアプリをリロードする。
   - 画面フッター等に表示されている内部バージョン番号が、今回反映したバージョンと一致していることを確認する。

> [!WARNING]
> Webアプリを「新規デプロイ」として作成し直すと、アプリのURLが変わってしまいます。URLが変わると、端末のブラウザ（LocalStorage）に保存されている運航中下書きデータ（`EVO_LITE_ACTIVE_OPERATION_V2`）や補助者履歴が引き継がれなくなるため、**原則として「既存デプロイのバージョン更新」を行ってください**。

## 4. 今後の変更時の注意点と安全チェックリスト

システムに機能追加・修正を行う際は、以下の原則とチェックリストを厳守すること。

### 4.1 作業の基本原則
- **調査の起点**: 必ず `docs/code-map.md` から影響するファイルと関数を特定する。
- **正本の遵守**: 変更は必ず `src/` 配下のソースコードに対して行う。`dist/Code.gs` を直接編集しない。
- **結合順の整合性**: 新規に `.gs` ファイルを作成した場合は、必ず `scripts/source-order.json` へ登録する。
- **変更の分離**: UIの文言・スタイル変更と、保存計画や帳票書き込みロジックの変更を同時に行わず、分離して進める。

### 4.2 入力項目追加・機能変更時の確認
新しい入力項目（フォーム項目）や機能を追加する場合は、**[docs/feature-guide.md](feature-guide.md) を参照して作業すること**。
UI、下書き（LocalStorage）、入力検証、署名、固定保存計画、帳票書き込み、回帰テストに渡る「全7層の一括確認チェックリスト」が正本として定義されている。二重管理を防ぐため、チェックリストの詳細は本書ではなく `feature-guide.md` に従うこと。

### 4.3 スプレッドシート連携変更時の注意
- **見出し検索と列オフセット**: 見出しテキスト（「使用バッテリー」「点検時の総飛行時間」等）を変更すると動的セル検出が壊れるため、コード側の検索文字列と完全に一致させること。
- **自由入力の保護**: 新しいテキスト入力欄を追加した場合、数式インジェクション防止処理（RichTextValue化）を必ず通過させること。
- **保存フェーズの追加**: 保存段階を追加する場合は、進捗の永続化、`SpreadsheetApp.flush()`、読み戻し検証、および障害注入テスト（T16〜T23）への項目追加をセットで行うこと。
- **complete再送の不変性**: 保存完了後のクライアント再送（T23ケース）において、二重加算や二重書き込みが絶対に起きない設計を維持すること。

### 4.4 画面・UI変更時の注意
- **レスポンシブ基準**: 430px以下（狭幅スマホ1列）、600px以上（2列）、761px以上（最大幅760px中央固定）のレイアウト崩れがないか確認すること。
- **タップ領域**: ボタン・チェック・チップは最低44px以上の高さを確保すること。
- **Safe Area**: `env(safe-area-inset-*)` が適用され、ノッチやホームバーと重ならないこと。
- **補助者履歴**: 前回値を不用意に自動選択せず、「なし」を安全なデフォルトとすること。
