# 第2章 法令・正式記録・運用方針

[設計書目次](../../01_ドローン運航記録_設計書.md) · [文書索引](../index.md)

本章は正式記録全体による評価、連続飛行・日跨ぎの採用方針、法令調査の判断基準を扱う。以下は既存設計で採用した運用と根拠の整理であり、今回の章分割による法令の再調査・新しい適合判定ではない。

## 正式記録全体で評価する

法令遵守を「国交省様式の全欄をWebフォーム化すること」と同一視しない。評価単位は **Webアプリ＋日常点検帳票＋BAT履歴＋機体原本＋点検整備記録＋必要時の手動補記** である。BAT管理等のアプリ独自情報を、法令上の常時必須事項と混同しない。

- 通常の運航・点検はアプリで記録し、運航終了時に確定する。既存値の引用、自動取得、機体別累計を活用する。
- 点検整備は実施時に原本を複製して記入・保管する。予定を実績にせず、原本の現在累計と過去の整備実績を分ける。採用理由・管理開始根拠は [第7章](07-maintenance-start.md) に置く。
- 日跨ぎ、不具合、処置、点検者・場所の相違等は条件発生時だけ補記する。自動入力と実態の不一致は、保存完了後の正規の手修正で整合させる（[第5章](05-records-manual.md)）。全条件の常設入力を要求しない。
- 機体概要は日誌冒頭・対応する別紙等へ集約できる。認証・技能証明情報は該当条件に応じて扱う。必要事項を一括して参照・提示できることを保つ。機体概要やメーカー点検条件は別紙・原本・メーカー資料・手動記録で確認する役割分担であり、Webアプリへの全自動実装や監査での未精査だけを理由に未解決としない。具体的な矛盾が見つかった場合に、その対象を確認する。

根拠：取扱要領4、5(3)、6／ガイドライン2②、3(3)。独自様式・電子記録・別管理が認められることと、必要な実施事実を未記録でよいことは区別する。

## 連続飛行・日跨ぎの扱い

- 同一エリア・同一目的の連続飛行について初回の全点検とBAT交換時の最小確認を採用する方針は、[第3章](03-workflow-ui.md)・[不変条件9](../invariants.md#9-ワンオペ現場操作の最小化)に定めるもの。
- ガイドライン4(1)①②は、機体認証を受けない機体の単一エリア・同一ミッションの連続飛行について、途中の電源OFF/ONを含めて1飛行として扱う柔軟な記載を認める。道路を隔てた隣接エリアも含む。正味の滞空時間を管理することが条件。
- **本アプリは一括記録が許容されても各飛行を1行ずつ残す既存仕様を維持する。** 法的に許容される集約単位とアプリの明細行を混同せず、過去行を合算・削除しない。点検頻度はガイドライン4(2)と適用するメーカー／飛行マニュアルの条件に従う。柔軟規定をすべての点検の省略許可としない。
- 取扱要領7(1)hは日跨ぎが分かる記載を求める。日付変更だけを理由に必ず2飛行・2運航に分割する要求ではない。1飛行のまま着陸が「翌日」等と分かる注記で扱える。
- 現行コードは離着陸時刻をHH:mmだけで出力する。日跨ぎした場合は既存の手動補記で着陸日を識別できるようにする。日跨ぎ自体を禁止したり、強制分割したりする新仕様は採用しない。

## 今後の法令調査・監査ルール

1. 原則だけで結論を出さず、例外、柔軟な取扱い、条件付き適用、独自様式・電子記録、別紙・手動補完を同時に確認する。
2. 本章・[第7章](07-maintenance-start.md)と[Spreadsheet仕様](../spreadsheet-spec.md)・[不変条件](../invariants.md)にある決定済み役割分担を先に読み、実運用上の制約と照合する。評価単位は上記の正式記録全体。
3. 「法令上必要」「ガイド上の推奨」「条件発生時のみ」「手動・別紙で充足」「アプリ独自仕様」を区別する。欄の不在だけで欠陥としない。
4. 新たな懸念も、既存の柔軟運用・手動補記・原本管理で適法に満たせるかを先に検討する。本当に自動実装が必要と裏付けられた場合だけ改修候補とする。
5. 再問題化する際は、既存判断の根拠、新しい法令・事実、影響する条件、代替手段では足りない理由を示す。既に原則・例外・柔軟な取扱い・実運用を検討して採用した事項は、法令変更または新事実がない限り、一般原則だけで未解決へ戻さない。既存の柔軟運用・手動修正・別紙・原本管理で処理可能な事項は、未解決課題に分類しない。
6. 既存判断も法令変更や反証があれば再評価する。ただし「確認済み運用」「法的評価」「未確認の個別事実」を分け、根拠不足を違反とも適合とも断定しない。

本章の採用判断は、既存設計・帳票・実装・2026-09-11の国交省資料確認と利用者の運用説明の照合に基づく。項目別の既存記載状況と前回評価の訂正理由は[再監査記録](../reports/flight-log-review-2026-09-11.md)に残す。
