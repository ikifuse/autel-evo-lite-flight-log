# スプレッドシート帳票・原本仕様書

## 1. 文書の位置づけ

本書は、Autel EVO Lite / Lite+ ドローン運航記録システムにおけるGoogleスプレッドシート（帳票および原本）の物理構造・セル配置・書式・記録ルールを定めた正式仕様書である。

- 関連正本仕様書: [01_ドローン運航記録_設計書.md](../01_ドローン運航記録_設計書.md)
- コード対応索引: [docs/code-map.md](code-map.md)
- ソースコード正本: `src/20_sheet_core.gs`, `src/21_sheet_records.gs`, `src/22_battery_history.gs`, `src/23_aircraft_totals.gs`

---

## 2. 必須シートと原本構成

本システムは、固定スプレッドシート内の以下のシート群を対象として動作する。

| シート名 | 役割 | 備考 |
|---|---|---|
| `日常点検` | 日付シート複製用原本テンプレート | No.1およびNo.2の2ブロックを持つ |
| `BAT_1` ～ `BAT_7` | バッテリー個別履歴シート（計7枚） | 13～212行がデータ履歴領域 |
| `点検整備記録_EVO Lite_原本` | EVO Lite専用の累計管理・原本 | 点検時の総飛行時間セルを保持 |
| `点検整備記録_EVO Lite+_原本` | EVO Lite+専用の累計管理・原本 | 点検時の総飛行時間セルを保持 |

## 3. 日常点検シート仕様

### 3.1 シート生成と命名規則

- 日付シートはテンプレート原本 `日常点検` を複製して作成する。
- 通常シート名: `YYYY.M.D`（例: `2026.9.7`）。
- 同一日の複数運航: 既に同日シートが存在しブロックに空きがない場合、または「本日別の新しい現場」として運航を開始した場合は、連番サフィックスを付与して新規作成する（例: `2026.9.7_2`, `2026.9.7_3`）。
- 「本日別の新しい現場」フラグが有効な場合、既存シートに空きブロックがあっても連番シートを新規作成してそこへ記録する。

### 3.2 ブロック構造

1枚の日常点検シートは、左右2つの記録ブロック（No.1 / No.2）で構成される。

| ブロック | 列範囲 | 最大飛行回数 | 備考 |
|---|---|---:|---|
| No.1 | C:O（3～15列） | 7飛行 | 1運航目の開始、または機体交代・8飛行目の受け皿 |
| No.2 | R:AD（18～30列） | 7飛行 | 同一日の2運航目、8飛行目以降、または交代機体 |

- 同一機体で8飛行目が発生した場合は、次の空きブロックへ記録を送る。
- 同一運航内で機体交代（EVO Lite ↔ EVO Lite+）を行った場合も、交代先機体は次の空きブロックを使用する。
- 1つのブロックに8行以上書き込むことは絶対にせず、両ブロックが使用済みの場合は次の連番日付シートを作成する。

### 3.3 ブロック内レイアウトと記録項目

各ブロックには以下の項目を配置・記録する。元の列幅、行高、セル結合、外観罫線はテンプレート原本の設定を維持し、変更しない。

1. **基本情報ヘッダー**: 機体名・登録記号、実施日、飛行目的、操縦者／補助者氏名、技能証明番号、飛行経路・場所、飛行カテゴリー、飛行方法。
2. **飛行前点検**: 11項目の点検結果（チェック欄に `☑` または `□` を記録）。
3. **飛行記録行（最大7行）**:
   - 飛行行の開始位置は固定行番号ではなく、見出しセル「使用バッテリー」を検索して動的に特定する。
4. **飛行後点検**: 4項目の点検結果（機体全般、プロペラ・フレーム、発熱、その他）、点検実施場所、異常の有無、不具合詳細、確認者。

### 3.4 飛行記録行の列構成

見出し「使用バッテリー」の行を基準として、各飛行行は以下の8列で構成される。

| 列順 | 項目名 | 記録形式・仕様 |
|---:|---|---|
| 1 | 使用バッテリー | `BAT_1` ～ `BAT_7` |
| 2 | 離陸場所 | 地名文字列、または座標付き2行形式 |
| 3 | 着陸場所 | 地名文字列、または座標付き2行形式 |
| 4 | 離陸時刻 | `HH:mm`（24時間表記、例: `09:15`） |
| 5 | 着陸時刻 | `HH:mm`（24時間表記、翌日着陸も許容） |
| 6 | 飛行時間 | `HH:mm`（実飛行分数から変換、例: 25分 → `00:25`） |
| 7 | 総飛行時間 | `HH:mm`（開始累計＋各飛行時間の積算、24時間超も保持） |
| 8 | 飛行の安全に影響のあった事項 | 文字列（特記事項なし時は空欄または定型） |

## 4. TEST日付シート仕様

- 飛行目的が完全一致で「`アプリテスト`」の場合に限り、通常の日付シートとは完全に分離した専用シートを使用する。
- シート命名規則: `TEST_YYYY.M.D`, `TEST_YYYY.M.D_2`, `TEST_YYYY.M.D_3` …
- 通常の日常点検シートとはブロック探索・使用判定も完全に分離する。
- 内容が空欄化されて構造が利用できない古いTESTシートは再利用せず、次の連番へ進む。
- 保存完了後にTESTシートを手動削除しても、新しいUUIDによる次回テスト時には必要な連番TESTシートを再生成する。
- 同じcomplete済みUUIDの再送時は、削除されたシートを再生成・復元することはせず、complete証明から正常応答のみを返す。

### 4.1 日付ブロックの固定予約

- 日付シートのownershipは、Script Properties上のfixed commit planに`sheetName`と`blockNo`を固定して記録する。
- 未完了planの割当てはactive reservationとして扱い、別draftの新規割当てから除外する。
- 同じdraftIdの再送では同じ固定セルをbefore/intendedで照合し、別ブロックを再選択しない。
- pending中の対象セルがbefore/intended以外なら競合停止する。complete後の手動修正・空欄整理は正常運用であり、次回保存を妨げない。
- 既存のDeveloper Metadataは削除しないが、新しい保存処理では読み書きせず、ownership判定にも使用しない。

## 5. バッテリー個別シート（BAT_1 ～ BAT_7）仕様

各バッテリーシートは、13行目から212行目までの計200行をデータ履歴領域として使用する。

### 5.1 列構成

| 列 | 項目名 | 内容・形式 |
|---:|---|---|
| A | 日付 | 運航日（`YYYY/MM/DD` 形式） |
| B | 機体 | 使用機体名（`EVO Lite` または `EVO Lite+`） |
| C | 飛行目的 | 業務目的（「アプリテスト」の場合もそのまま記録） |
| D | 飛行時間（分） | 当該飛行の実飛行時間（整数、分単位） |
| E | サイクル数 | Autel Sky等で確認できた場合の充電サイクル数（任意、数値） |
| F | BAT異常・所感 | バッテリーの異常・発熱・劣化等の所感テキスト |
| G | 飛行経路・場所 | 離陸場所・飛行場所 |
| H | 予約 | 将来拡張用・予約領域 |

### 5.2 行の決定と固定予約

- 新規保存計画の作成時に、第1列（A列）が空欄である最初の行を走査して予約する。
- 予約した`sheetName`、`row`、`flightIndex`をfixed commit planへ保存し、active pendingの同じ行は別draftの候補から除外する。
- 保存再試行時は行を再選択せず、固定したA:Hの各セルをbefore/intendedで照合して二重追記を防止する。
- 表示セルの内容が保存完了後に利用者によって手動で空欄化された場合、新しいUUIDの運航はその空き行を再利用できる。
- 保存処理中（pending状態）の手動セル変更は競合検知により安全に停止する。
- 既存のDeveloper Metadataは保持するが、保存・診断・復旧・行選択の判断材料にはしない。

## 6. 機体原本と機体累計時間仕様

### 6.1 原本シート構成

- EVO Lite用: `点検整備記録_EVO Lite_原本`
- EVO Lite+用: `点検整備記録_EVO Lite+_原本`

### 6.2 累計セルの検出規則

- シート内の固定セル座標（番地）に依存せず、ラベル文字列「`点検時の総飛行時間`」をシート内から一意に検索する。
- そのラベルに隣接する右側（または直下）のセルを機体累計時間セルとして動的に特定する。

### 6.3 累計計算と更新ルール

- 本システムでの管理開始時の初期累計時間は、両機体ともに `00:00`（BATも `00:00`）から開始し、過去の紙や別台帳の履歴を遡って逆算・変更しない。
- 通常運航時:
  1. 保存計画作成時に原本の累計セルから開始累計時間を読み取る。
  2. 日付シート内の各飛行行に、各飛行時間を加算した途中累計（`HH:mm`）を書き込む。
  3. 計画された全飛行の合計時間を加算した最終累計値を、機体原本シートの累計セルへ反映する。
  4. 同一運航内で2機種を使用した場合は、機種ごとに独立して計算・更新する。
- アプリテスト時:
  - 正式な機体累計を開始値として読み取り、TEST日付シート内では飛行ごとの積算累計を表示するが、**機体原本シートの正式累計セルは絶対に更新しない**。
- 点検整備記録原本の手動運用:
  - 点検整備記録そのものは毎回の飛行ごとの記録ではなく、定期点検、修理、部品交換等のタイミングで利用者が原本を複製して手動で記入・保管する運用とする。

## 7. セル内の場所表示と書式ルール

運航開始画面・離陸画面・着陸画面で入力された「飛行経路・場所」「離陸場所」「着陸場所」は、すべて同一の表示整形ルールを適用してセルへ書き込む。

| 入力パターン | セル表示形式 | 適用書式 |
|---|---|---|
| **名称のみ** | 入力された地名・施設名を1行表示 | 通常文字サイズ、横中央、縦中央 |
| **GPS座標のみ** | 座標文字列（`(緯度, 経度)`）を1行表示 | 通常文字サイズ、横中央、縦中央 |
| **名称 ＋ GPS座標** | 1行目に名称、2行目に改行して `(緯度, 経度)` | **文字サイズ1pt縮小**、**折り返して全体を表示**、横中央、縦中央 |

- 座標判定には、前後空白を除去（trim）した値を使用する。
- 座標形式ではない文字列入力については、入力者が意図して入力した先頭空白やタブを保持して安全に保存する。
- 表示整形の適用時も、シートの既存列幅・行高は変更しない。
