## 2. ドキュメントの役割分担

無駄なコンテキスト消費と記述の重複を防ぐため、各文書は明確に役割を分担している。

```text
[入口・行動規範]
  AGENTS.md ...................... 最短の行動ルールと参照方針 (最初に見る)
    │
    ├─► docs/index.md ............ 本書 (ドキュメント案内所)
    │
    ├─► docs/code-map.md ......... コードの辞書・索引 (該当ファイル特定)
    │
    ├─► docs/invariants.md ....... 絶対防衛線 (壊してはならない条件と理由)
    │
    ├─► docs/architecture.md ..... 全体構造 (データの流れ・ビルドの把握)
    │
    ├─► docs/feature-guide.md .... 拡張手順書 (新項目追加時の全層チェック)
    │
    └─► [詳細リファレンス群]
          ├─ 01_ドローン運航記録_設計書.md ... 総合的な設計仕様・正本
          ├─ docs/spreadsheet-spec.md ........ シート物理構造・セル番地
          ├─ docs/test-spec.md ............... テストケース詳細仕様
          └─ docs/rebuild-guide.md ........... 再構築・GASデプロイ手順
```

---

## 3. 開発・保守時の参照ルール

1. **必要な文書だけを読む**:
   一度にすべてのドキュメントを読み込まず、上記「目的別の最短ナビゲーション」に従って該当文書のみを参照すること。
2. **正本を遵守する**:
   コードの正本は `src/` 配下であり、ドキュメントの記述と実コードに差異がある場合は、不変条件に抵触しない限り実コードおよび正本仕様書の記述を優先すること。
