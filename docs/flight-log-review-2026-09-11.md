# 飛行日誌の再監査・決定済み運用の文書化（2026-09-11）

## 結論

前回の「未実装・運用上の不足（未解決）」という一括評価を訂正する。法定記録をWebアプリだけで完結させる設計ではなく、アプリ・日常点検帳票・BAT履歴・機体原本・点検整備記録・必要時の手動補記を合わせて評価する。整備の手動記録、条件付きの補記、各飛行1行と一連の点検運用は意図した役割分担であり、常設入力欄がないことだけで未解決としない。

正式な運用思想・採用根拠・監査ルールは[正式設計書2.1～2.4](../01_ドローン運航記録_設計書.md#21-正式記録全体で評価する決定済みの役割分担)に集約した。根拠に反する新事実を無視する固定化ではなく、再評価時に新しい根拠と影響条件を明示するルールである。

## 機体別の確認結果と残る限定事項

Lite+の初期確認記録には、2026年9月1日、中古取得以前の正確な累計不明、初期確認、管理開始00:00が明記されている。予定の装備についても実際の交換実績ではない旨が記録されており、予定・実績の分離は利用者の記憶だけに依存する説明ではない。

Liteは原本の累計00:00を確認したが、実施日・理由は空欄だった。新品購入という今回の申告と整合するものの、購入日・初飛行日・以前の利用実績の不存在を原本が証明するとはしない。中古記録欠落の問題をそのまま適用しない。

残る確認は次に限定する。これを整備自動生成・入力欄追加の課題へ戻さない。

1. 記録欠落時の柔軟な0:00起算は公式に存在する。一方、2026年中古取得日を起点とする個別事案の明示は確認できず、肯定・否定を行政判断済みとは言えない。起算説明が点検整備記録にあることは確認済みだが、ガイドラインが挙げる飛行記録冒頭・表紙への対応は未確認。
2. 初期確認記録の屋内短時間飛行の算入除外は、メーカー出荷前完成検査の除外では正当化できない。ガイドライン別添1-3には屋内飛行の加算例があるため、「屋内／初期確認だから当然除外」とは断定できない。これは不明な前所有者の時間を推定する話とは別である。
3. 現行の日付帳票の記事欄は計画作成日を出力する。予定・実績を区別した正式運用と矛盾する出力になった場合の手動整合は必要であり、コードが自動で判別済みとは書かない。
4. 実際の機体概要別紙、適用するメーカー点検条件・承認済み飛行マニュアルとの詳細照合は今回の実証範囲外。全運用への適合保証はしていない。

今回の作業は設計・運用文書のみ。コード、帳票、画像、PDF、Spreadsheet、Properties、pending、GASを変更していない。
