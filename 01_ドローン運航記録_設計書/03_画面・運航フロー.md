# 第3章 画面・状態遷移・運航フロー

[設計書目次](00_目次.md) · [文書索引](../docs/index.md)

本章は画面の役割と運航の進行を扱う。状態データのフィールド・通信契約は [architecture](../docs/architecture.md)、担当コードは [code-map](../docs/code-map.md) を参照する。

## 画面と状態遷移

クライアントは運航状態を描画し、開始後はsessionを保持して最終保存まで帳票への書込みを行わない。

### 画面一覧

| phase | 主な画面 |
|---|---|
| 運航外 | 開始画面 |
| `PRE` | 飛行前点検 |
| `PRE_ABNORMAL` | 飛行前点検の異常内容 |
| `BATTERY_CHANGE` | 交換BATの装着・ロック・状態確認 |
| `READY` | 離陸待機 |
| `FLYING` | 飛行中 |
| `LANDING` | 着陸後入力 |
| `AFTER_LANDING` | 継続、BAT交換、機体交代、終了の選択 |
| `POST_ALL` | 使用機体ごとの飛行後点検と最終保存 |

開始画面には不要な「戻る」を表示しない。運航中はクライアント内の `navigationHistory` に直前状態のスナップショットを積み、「一つ前の画面に戻る」で復元する。戻った後の再入力が現在状態を上書きする。

### 正常な流れ

```text
開始条件入力
→ 最初の機体の飛行前点検
→ 離陸待機
→ 飛行中
→ 着陸後入力
→ 続行判断
   ├─ 同じ機体・同じBATで次の離陸
   ├─ BAT交換の最小確認
   ├─ 機体交代後、新機体の飛行前点検
   └─ 全飛行終了
→ 使用した全機体の飛行後点検
→ 一括保存
→ トップ画面
```

### session構造

運航識別・機体別状態・飛行明細・点検・入力退避を保持する。フィールド対応は [構造仕様8](../docs/architecture.md#8-sessionのデータ契約) を参照する。

## 運航開始

開始画面では、機体、飛行経路・場所、飛行目的、天気・風速・風向、飛行カテゴリー、飛行方法、許可承認番号、操縦者、補助者、技能証明番号を扱う。天気・風速・風向は任意で、未選択時は空欄のまま保存する。前回条件を引用できるが、補助者は誤記防止のため自動選択しない。

操縦者は一人の固定値を初期表示し、技能証明番号は未所持を前提に空欄で扱う。補助者は「なし」「過去の氏名」「新しい人を入力」から選ぶ。履歴には氏名だけをtrim・重複除去して保存し、新しい氏名は運航開始成功後に追加する。前回の補助者は候補に加えても自動選択しない。データ上は補助者なしを空文字、ありを氏名で表す。

運航識別子は開始時に生成し、保存失敗でも同じ運航として再送する（[第4章](04_保存・復旧.md)）。

## 飛行方法とカテゴリー

選択肢は、通常飛行・屋内練習と、9項目の特定飛行で構成する。

| 飛行方法 | 画面上の簡易補足 |
|---|---|
| 通常飛行（特定飛行なし） | 特定飛行に該当しない通常の飛行 |
| 屋内練習 | 四方・上部が囲まれた屋内での練習 |
| 空港等周辺 | 空港周辺等 |
| 150m以上 | 地表・水面から150m以上 |
| DID | 人口集中地区 |
| 夜間 | 日没〜日の出 |
| 目視外 | 直接目視しない飛行 |
| 30m未満 | 第三者・物件から30m未満 |
| 催し場所上空 | イベント等の上空 |
| 危険物輸送 | 危険物を輸送 |
| 物件投下 | 飛行中に物件を投下 |

合計9種の特定飛行項目には、それぞれ短い補足を表示する。「通常飛行」は他項目と同時選択できない。屋内練習の排他を含む最終整合性はサーバーでも検証する。

カテゴリーⅠで特定飛行項目を選ぶとカテゴリーⅡへ自動変更し、約3秒の通知を表示する。該当項目をすべて外した場合はⅠへ戻る。カテゴリーⅢは許可・機体・操縦者等の条件を画面だけで確定できないため、自動選択しない。必要な特定飛行には、許可・承認や安全措置を確認する補足を表示する。

## 飛行前点検

最初の飛行前点検は、機体へ使用BATを装着し、電源投入後に行う。画面には区分と確認内容を並べ、未確認状態から操縦者がチェックする。

1. 機体全般
2. プロペラ・フレーム
3. 通信系統
4. 推進系統
5. 電源系統
6. 自動制御系統
7. バッテリー
8. 操縦装置（プロポ）
9. 灯火
10. カメラ
11. リモートID

機体に装着中のBAT番号は必須である。現在のサイクル数はAutel Skyで確認できた場合だけ任意入力する。異常がある場合は異常内容を記録し、安全に進行できない状態では運航を中止する。

## 離陸・飛行・着陸

### BAT交換

同じ機体で継続するときは全11項目を繰り返さず、次のBATについて番号、装着・ロック、残量・温度・警告状態を確認する。機体を交代した場合は、交代先機体で最初の飛行前点検を行う。

### 離陸待機と飛行中

離陸待機ではBATと離陸場所を確認する。「離陸を記録」で離陸時刻を確定し、飛行中画面へ進む。飛行中は操縦に集中し、着陸後に記録操作を行う。

### 着陸後入力

「着陸完了」により着陸時刻を確定する。着陸場所、実飛行時間（分）、安全に影響した事項、BAT所感等を入力する。実飛行時間はAutel Skyの値を使用する。分数・件数の上限は [入力境界](../docs/architecture.md#10-入力境界の詳細) を正本とする。

日時はISO形式の実時刻で比較するため、23:55離陸・翌日00:10着陸のような日付またぎを許容できる。着陸は離陸以後かつ24時間以内でなければならない。帳票の時刻表示は `HH:mm`、日付シートは運航開始日を基準にする。

日跨ぎの運用判断は [第2章](02_法令・運用.md)、帳票への日付補記は [第5章](05_記録・手動補記.md) に従う。

## 機体交代と飛行後点検

EVO LiteとEVO Lite+を同じ運航内で交代できる。交代先の機体は使用済みとして登録し、その機体で初回の飛行前点検を要求する。帳票では機体ごとに別のNo.ブロックを割り当てる。

全飛行終了後、使用した各機体について次の4項目を未確認状態から点検する。

1. 機体全般
2. プロペラ・フレーム
3. 発熱
4. その他

点検実施場所、異常なし／不具合あり、不具合箇所、事象等、確認者を記録する。異常なしを初期選択しない。

最終保存の成功時にトップへ戻り、失敗時は画面と下書きを保持する。描画・下書き消去・通知の順は [第4章](04_保存・復旧.md) に従う。

## 場所入力とGPS

飛行経路・場所、離陸場所、着陸場所は手入力とGPS取得に対応する。取得結果から地名を入力し、座標も保持する。取得失敗時も手入力できる。前回条件引用は直前運航の場所等を戻す。お気に入り場所一覧・登録・名称変更・削除のUIと専用localStorageは廃止済みである。

外部送信先と個人情報の扱いは [第8章](08_セキュリティ・品質.md)、タイムアウト・失敗処理の変更手順は [feature-guide](../docs/feature-guide.md#4-外部api連携時の注意gps逆ジオコーディング等)、セル表示は [Spreadsheet仕様7](../docs/spreadsheet-spec.md#7-セル内の場所表示と書式ルール) を参照する。

## 端末幅と操作性

Pixel 6aの縦向きを基準に、狭い画面でも確認・入力しやすい操作面を保つ。横向き専用レイアウトは設けず、縦向きを通常運用とする。折りたたみ端末やタブレットでも端末名ではなく幅で表示を変え、レスポンシブ変更によって保存データ構造や状態遷移を分岐させない。

最大幅・幅別の列数・操作高・Safe Areaの詳細は [feature-guide](../docs/feature-guide.md#3-uiデザインスタイル変更時の手順) と [再構築ガイド4.4](../docs/rebuild-guide.md#44-画面ui変更時の注意) を正本とする。
