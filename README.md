# AUTEL EVO Lite / Lite+ ドローン運航記録システム
（国土交通省 飛行日誌対応・完全無料・現場運用特化 Webアプリケーション）

航空法第132条の89に基づく無人航空機の飛行日誌を、現場で順番に確認・入力するためのGoogle Apps Script（GAS）ベースのWebアプリケーションです。

現在の現場運用版：**v2026.09.05.4**

この版では、装着済みBATを飛行前点検で選択し、同一現場・同一目的の連続飛行ではバッテリー交換時の確認を必要箇所だけに限定しました。現場・目的が変わる場合は、既存の同日連番シートへ運航を分けます。

## 本システムの運用思想（現場実務への適合）

本アプリは、航空法第132条の89に基づく飛行日誌の作成・携行・保管を支援しながら、ワンオペの現場で安全確認と記録を迷わず完了させるための運航記録ツールです。

確認項目を機械的に増やすのではなく、法規、安全、機体の取扱説明書および適用する飛行マニュアルを守ったうえで、現場で確認できる内容を、確認できる時点で、必要最小限の操作により記録することを基本方針としています。

### 連続飛行の実務に合わせた点検

機体認証を受けていない機体を、単一の飛行エリア内で同一目的・同一ミッションのため連続して飛行させる場合は、国土交通省[「無人航空機の飛行日誌の取扱いに関するガイドライン」](https://www.mlit.go.jp/common/001599241.pdf)の柔軟な取扱いを利用します。

- 一連の連続飛行を始める前に、装着済みBATを含む正式な飛行前点検を実施します。
- BATのサイクル数は、装着後にAutel Skyで確認できる場合だけ任意入力します。
- 同じ機体でバッテリーを交換して続ける場合は、交換後のBAT番号、装着・ロック、残量・温度・警告表示を確認します。
- バッテリー交換ごとに11項目の正式点検を繰り返すことは、標準運用として要求しません。
- 飛行後点検は、一連の連続飛行がすべて終了した撤収時に実施します。
- 異常、衝突、接触、警告表示などが発生した場合は、連続飛行を中止して必要な点検・整備・記録を行います。

飛行エリア又は目的が変わる場合は、現在の運航を確定し、同日の別運航として連番シートへ記録します。未点検の別機体へ交代する場合は、その機体の正式な飛行前点検を実施します。

### 飛行記録とバッテリー履歴の一括保存

日付シートの飛行記録欄には、実際に飛行した回数分を使用BATごとに1行ずつ記録します。複数のBATで飛行した記録を、合計時間だけの1行へ集約しません。

No.1／No.2の各記録枠には最大7飛行を記入します。同一機体で8回以上飛行した場合は、7飛行ごとに次の空き記録枠へ続けます。1枚のNo.1とNo.2が埋まった場合は、`日付_2`、`日付_3`の同日連番シートへ自動的に続けます。

運航中は、各離着陸、使用BAT、個別飛行時間および確認できたサイクル数を未確定下書きとして個別に保持します。飛行後点検が完了した時点で、飛行回数分の行を日付シートへまとめて送信し、同時にBAT_1〜BAT_7の該当シートへ各BATの履歴を個別保存します。

ここでいう「一括保存」は、複数飛行を1行へ合算する意味ではありません。運航途中でスプレッドシート通信を行わず、最後に各飛行の行をまとめて書き込むという意味です。

点検周期やバッテリー交換時期は、一律の法定値として自動決定せず、使用している機体・バッテリーの取扱説明書、メーカー情報、実際の状態および適用する整備基準に従って判断します。

### 戻る・中断・通信断への対応

運航中の入力は、飛行後点検が完了するまでスプレッドシートへ逐次書き込みせず、1件の未確定下書きとして端末内に保持します。

- 各画面から一つ前へ戻り、チェックや入力内容を修正できます。
- 修正後に進み直した場合は、以前の内容を残さず最新の内容で上書きします。
- 初期画面には、戻り先がないため「一つ前の画面に戻る」を表示しません。
- 飛行後点検は未確認状態から開始し、実機確認前に「正常」と記録しません。
- 最終保存の通信に失敗した場合は未確定下書きを保持し、通信復旧後に再度保存します。
- 最終保存が成功した後は、端末内の未確定下書きを自動削除します。

### 設計・開発方針

新しい入力項目や機能は、法規・安全上の必要性、現場で確認できる時点、自動化の可能性、操作負担、虚偽記録の防止、戻る・中断・通信断への耐性、最終記録の完全性という7つの基準で判断します。

詳しい判断基準は [01_ドローン運航記録_設計書.md](./01_ドローン運航記録_設計書.md) を参照してください。

### Webアプリとスプレッドシートの役割分担

- **現場のWebアプリ**：運航条件、飛行前点検、離着陸、バッテリー・機体交代、飛行後点検、最後の一括保存だけを扱います。
- **自宅でのスプレッドシート管理**：点検整備記録（様式3）の記入、保存後の誤記訂正、記録の検索・確認・印刷を行います。
- Webアプリに「点検整備」「日誌PDF・検索」「記録訂正」の画面は設けません。毎回の運航と頻度の低い管理作業を混在させず、現場で迷わないことを優先します。
- 既存の点検整備記録や訂正履歴は削除しません。過去の記録としてスプレッドシート内に保持します。
- 飛行日誌はスマートフォンからGoogle Drive／Googleスプレッドシートで参照・提示できる状態にします。通信圏外での提示が必要になる場合のオフライン保存は、必要な運航の前に個別に判断する注意事項とし、Webアプリの通常工程には加えません。

追加費用や有料APIは一切使わず、Googleアカウント（無料）のみで動作します。

* **点検整備記録_原本（様式3）**：定期点検、部品交換、修理又は改造を実施した時に、スプレッドシート上でコピーして手動記入する原本です。Webアプリの毎回の運航工程からは分離しています。
* **日常点検シート（様式2）**：A4横向き1枚（左側：No.1枠 / 右側：No.2枠）で完結する設計
* **BAT_1 〜 BAT_7**：バッテリー7本の個別サイクル・履歴管理シート
* **既存の訂正履歴等**：過去データとして保持しますが、Webアプリから新規作成・追記しません。

> [!TIP]
> **法定記録を残しながら、現場の操作を増やさない設計思想**
> Webアプリは、現場で毎回必要となる飛行記録（様式1）と日常点検記録（様式2）の作成に集中します。点検整備記録（様式3）は、実施した時にスプレッドシートの原本へ手動記入します。

## 🚀 主な特徴と現場最適化機能

### 1. 運航途中の下書き保持
* **途中ではスプレッドシートへ書き込まない**：「運航開始」「飛行前点検」「離陸」「着陸」「機体交代」「飛行後点検」の順番で操作し、全フライトが終わるまで1件の運航下書きとして端末に保持します。
* **最後に一括保存**：飛行後点検を完了した時点で、飛行記録・日常点検記録・バッテリー履歴を1回の通信でスプレッドシートへ書き込みます。
* **途中で戻って修正可能**：読み込み済みの画面では進む・戻る・入力修正ができます。最後の確定通信に失敗した場合は下書きを残し、通信復旧後に確定ボタンを押します。
* **入力途中の復元**：進行中の運航下書きは1件だけ端末に保持し、ブラウザを再読み込みした場合も同じ段階から再開できます。確定保存または運航中止後に自動削除します。

### 2. 気象情報（天候・風速・風向）のワンタップ入力
* 天候・風速・風向はいずれも未選択から始まる任意入力です。未入力でも運航を進められ、選択した項目だけを保存します。
  * **天候**：`[晴]`, `[曇]`, `[雨]`, `[強風注意]`
  * **風速**：`[0〜1m/s 静穏]`, `[2〜3m/s 穏やか]`, `[4〜5m/s 注意]`, `[6m/s以上 飛行不可]`
  * **風向**：`[北]`, `[北東]`, `[東]`, `[南東]`, `[南]`, `[南西]`, `[西]`, `[北西]`
* 選択したデータだけが「飛行目的（飛行概要）」セルの末尾に自動結合され、未選択項目は空欄のまま保存されます。

### 3. 2機交互運航（Lite ↔ Lite+）のスムーズな機体交代
* 機体の熱対策やバッテリー運用のために日中に機体を切り替える際、着陸後画面の **[ 🔄 機体を交代する ]** ボタンで即座に切り替え可能。
* 朝入力した現場情報（場所・操縦者・目的等）は自動引き継ぎされ、無駄な再入力がありません。

### 4. 連続飛行を止めない点検フロー
* 同一現場・同一目的で続ける場合、正式な飛行前点検は運航開始時に実施し、バッテリー交換時はBAT番号・装着ロック・残量／温度／警告表示だけを簡易確認します。
* 飛行後点検は撤収前に**今回の運航で実際に飛ばした機体だけ**を確認します。チェックは未確認状態から始まり、実機確認後に「全て正常（実機確認済み）」を使用できます。
* 機体を初めて交代するときは、交代先の機体について正式な飛行前点検を実施します。すでに点検済みの機体へ戻る場合は、交換後のバッテリー確認へ進みます。

### 5. 午前・午後・複数現場の移動に対応（自動連番シート）
* 1日に複数箇所（午前と午後など）を移動して運航する場合、トップ画面の **「🏢 本日別の新しい現場として連番シートで開始する」** を選ぶことで、`2026.9.4_2`、`2026.9.4_3` と別シートが自動生成され、独立した日誌として提出・管理できます。

### 6. 現場記録と自宅管理の分離
* **飛行記録（様式1）**：離着陸場所・時刻、実飛行時間、総飛行時間の自動積算、安全影響事項
* **日常点検記録（様式2）**：飛行前11項目、飛行後4項目、異常時の特記事項・処置内容
* **点検整備記録（様式3）**：点検整備を実施した時に、自宅でスプレッドシートの`点検整備記録_原本`へ手動記入
* **検索・印刷・訂正**：保存済み記録をGoogleスプレッドシートから直接確認して実施

### 7. 行政・確認対応
* **国土交通省 許可・承認情報**：東空運/阪空運番号の保持、期限切れ30日前警告＆期限切れ赤色アラート
* **記録の携行**：スマートフォンのGoogle Drive／Googleスプレッドシートから記録を参照・提示します。通信圏外での提示が必要な場合だけ、事前のオフライン保存を個別に検討します。

## 📱 運航の流れ（迷わない現場最短ルート）

1. **現場到着（朝）**：
   * 現場情報を入力し、必要に応じて天候・風速・風向を選択します。
   * 使用するバッテリーを機体に装着・電源投入し、BAT番号を選択してから飛行前点検を行います。サイクル数はAutel Skyで確認できる場合だけ任意入力します。
   * 飛行前点検は未チェックで表示し、各区分の横にある具体的な確認内容を実機で確認してからチェック。「全て正常（実機確認済み）」も利用できます。
   * 運航開始後の戻る操作は、画面上部の「一つ前の画面に戻る」に統一。スプレッドシートへ書き込む前の下書きを1画面ずつ戻し、チェックや文字をその場で直して上書きできます。戻り先のない初期画面では表示しません。
2. **飛行・着陸（日中）**：
   * 点検済みのBATで「離陸開始」を押すと離陸時刻を自動保持します。「着陸完了（プロペラ停止後）」を押した時点で着陸時刻を保持します。
   * 飛行中画面には経過時間と「着陸完了（プロペラ停止後）」だけを表示し、操縦に集中できます。
   * 着陸後入力画面でAutel Skyに表示された飛行時間（分）などを入力して確定。GPS取得は任意です。
   * 「同じ機体で続ける（バッテリー交換）」では交換後のBATだけを簡易確認します。「機体を交代する」では、交代先が未点検の場合だけ正式な飛行前点検を行います。
3. **撤収（夕方）**：
   * 「全飛行を終了」を押し、今回の運航で飛ばした機体の飛行後点検を実施します。
   * 確定ボタンで全記録をスプレッドシートへ一括保存し、初期画面へ戻ります。

### 同じ日でも運航を分ける基準

* 同じ現場・同じ目的の連続飛行とバッテリー交換は、同じ運航下書き・同じ日付シートで継続します。
* 同じ条件でLiteとLite+を交代する場合は、同じ日付系列の空いているNo.1／No.2枠を使用します。両方埋まっている場合は同日連番シートへ続けます。
* 現場または目的が変わる場合は、現在の運航を確定し、トップ画面の「本日別の新しい現場として連番シートで開始する」を選びます。`日付_2`、`日付_3`のように独立して保存されます。
