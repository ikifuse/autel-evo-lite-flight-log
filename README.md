# Autel EVO Lite / Lite+ ドローン運航記録

Pixel 6aなどのスマートフォンから、飛行前点検・各飛行・バッテリー交換・機体交代・飛行後点検までを順番に入力し、Googleスプレッドシートへ運航記録を保存するGoogle Apps Script（GAS）Webアプリです。

- 公開版: **v1.0.0 — Initial stable release**
- 現行アプリ内部版: **2026.09.09.3**
- 対象機体: **Autel EVO Lite / EVO Lite+**
- 主な利用環境: **Pixel 6aの縦画面**

`v1.0.0` は公開リポジトリとしての安定版を示し、`2026.09.09.3` はアプリ内で表示・管理する実装バージョンです。

## このアプリの目的

法令上必要な記録を残しながら、ワンオペの現場で迷わず短時間に入力できることを目的としています。

単に入力項目を増やすのではなく、次の両立を重視しています。

- 飛行前に実機を確認し、安全上必要な順序を守る
- 飛行中の操作を最小限にする
- 同一現場・同一目的の連続飛行を、バッテリー交換や機体交代を含めて扱う
- 各飛行を1行ずつ記録し、機体・バッテリーの管理にも利用する
- 最後に正式な記録として不足なく保存する
- 戻る・中断・通信断・保存再試行でも記録の整合性を守る

本アプリは記録作成を支援する専用ツールです。飛行可否の判断、許可・承認の要否確認、機体整備、安全確保そのものを代替するものではありません。

## 主な機能

- 最初の飛行前に、装着済みバッテリーと11項目の飛行前点検を確認
- 離陸・着陸、飛行時間、安全影響事項を各飛行ごとに記録
- 同じ機体でのバッテリー交換と、EVO Lite / Lite+間の機体交代
- 1ブロック7飛行、No.1 / No.2、同日連番シートへの自動割り当て
- BAT_1～BAT_7へのバッテリー別履歴保存
- 機体別の累計飛行時間管理
- 全飛行終了時の飛行後点検と一括保存
- 保存途中で失敗した場合の、安全な同一運航再試行
- 通信圏外を含む入力途中の下書き保持
- GPS取得、手入力、前回条件の引用
- 補助者名の端末内履歴からの選択、または新規入力
- 通常運航と分離した「アプリテスト」記録
- Pixel 6aを基準にしたレスポンシブ表示
- ユーザー入力の数式実行防止と、サーバー側入力検証

## 現場での基本操作

1. 開始画面で機体、場所、目的、飛行方法、操縦者・補助者などを確認します。
2. 機体に使用するバッテリーを装着し、飛行前点検を行います。
3. バッテリー番号と離陸場所を確認して離陸を記録します。
4. 着陸後に着陸場所、実飛行時間、安全に影響した事項などを記録します。
5. 続ける場合は、同じ機体でバッテリー交換するか、別の機体へ交代します。
6. 一連の飛行を終えるときに、使用した機体ごとの飛行後点検を行います。
7. 「運航日誌を確定する」で、日付シート・BAT履歴・機体累計を一括保存します。

入力途中は「一つ前の画面に戻る」で前工程を修正できます。保存失敗時は下書きを残したまま、同じ運航を再度確定すると、最初に確保した保存先へ安全に再開します。

## 作成される記録

- 通常運航の日付シート: `2026.9.7`、`2026.9.7_2` …
- アプリテスト用シート: `TEST_2026.9.7`、`TEST_2026.9.7_2` …
- バッテリー履歴: `BAT_1`～`BAT_7`
- 機体別累計: `点検整備記録_EVO Lite_原本`、`点検整備記録_EVO Lite+_原本`
- 点検整備記録: 原本を利用者が必要時に複製・記入して管理

日付シートでは、1回の飛行を1行として保存します。1つのNo.ブロックには最大7飛行を記録し、同じ機体の8飛行目以降や機体交代時は次の空きブロックへ進みます。No.1 / No.2が埋まると、同日の連番シートを作成します。

「アプリテスト」でも日付シート内の累計値とBAT履歴は通常と同様に記録しますが、正式な機体累計マスターは更新しません。

## リポジトリ構成

| パス | 役割 |
|---|---|
| `src/` | 開発用GASソースの唯一の正本 |
| `dist/Code.gs` | GASへ貼り付ける自動生成済み統合版 |
| `scripts/source-order.json` | `src/` の結合順 |
| `scripts/build.mjs` | `dist/Code.gs` の生成・一致検証 |
| `tests/regression.test.js` | 回帰・障害注入・セキュリティーテスト |
| `.github/workflows/build-dist.yml` | 自動ビルド・検証・`dist`反映 |
| `01_ドローン運航記録_設計書.md` | 挙動、保存仕様、復旧設計を含む技術設計 |
| `docs/index.md` | 目的別の文書ナビゲーション・ドキュメント索引 |
| `docs/invariants.md` | 変更時も維持すべきシステムの前提条件・不変条件 |
| `docs/architecture.md` | 全体データフロー・実行構造・ビルド概要 |
| `docs/feature-guide.md` | 機能追加・変更時の標準手順と全層チェックリスト |
| `docs/code-map.md` | 変更目的から担当ファイル・関数を探す索引 |
| `AGENTS.md` | このリポジトリで作業するエージェント向けの短い規約 |

ルート直下に旧 `Code.gs` はありません。開発時は `src/` を変更し、GASへの反映には必ず `dist/Code.gs` を使用します。

## GASへの反映手順

通常、利用者が確認するのは次の2点だけです。

1. GitHub Actionsが成功していること
2. 最新の `dist/Code.gs`

反映手順は次のとおりです。

1. `dist/Code.gs` の全文をコピーします。
2. GASプロジェクトの `Code.gs` を全文貼り替えします。
3. GASで保存します。
4. 既存Webアプリのデプロイを更新します。
5. Pixel側でWebアプリを再読み込みします。

`src/` の各 `.gs` ファイルをGASへ個別に貼る必要はありません。`dist/Code.gs` は自動生成物なので、直接編集しないでください。

開発者向けのビルド、分割構成、保存の冪等性、テスト、障害復旧などの詳細や各文書の役割は、[ドキュメント案内](./docs/index.md)、[設計書](./01_ドローン運航記録_設計書.md)、[コードマップ](./docs/code-map.md)を参照してください。
